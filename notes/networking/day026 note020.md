# 2. Nmap Review

Nmap remains one of the most important reconnaissance tools.

Primary objectives:

- Discover active hosts
- Identify listening ports
- Detect running services
- Gather intelligence before interaction

Commands reviewed:

```bash
nmap localhost

nmap -p 31000-32000 localhost

nmap -sV -p 31000-32000 localhost

nmap -T4 -p <ports> localhost
```

---

# 3. Important Nmap Options

## -p

Scans only selected ports.

Example:

```bash
nmap -p 22,80,443 localhost
```

---

## -sV

Attempts service version detection.

Useful for identifying:

- SSH
- HTTP
- HTTPS
- FTP
- Unknown services

---

## -T4

Timing Template 4

Purpose:

Increase scanning speed.

Suitable for:

- Local machines
- Fast networks
- Laboratory environments

Avoid using aggressive timing on unstable production systems.

---

## Verbose Mode

```bash
nmap -v
```

Displays additional scan information.

Useful during troubleshooting.

---

## Extra Verbose

```bash
nmap -vv
```

Displays even more scan progress and technical information.

---

## Saving Scan Results

Normal report

```bash
nmap localhost -oN report.txt
```

XML

```bash
nmap localhost -oX report.xml
```

All formats

```bash
nmap localhost -oA report
```

Professional penetration testers always preserve reconnaissance results.

# 5. OpenSSL Client

Primary command

```bash
openssl s_client -connect hostname:port
```

Purpose:

Connect securely to SSL/TLS-enabled services.

Useful for:

- Manual testing
- CTF challenges
- Service verification
- Certificate inspection

---

## Useful Options

Quiet output

```bash
openssl s_client -quiet
```

Display certificates

```bash
openssl s_client -showcerts
```

Ignore EOF

```bash
openssl s_client -ign_eof
```

---

# 6. Understanding EOF

EOF means:

End Of File

Usually generated by:

Ctrl + D

Normally, applications terminate after receiving EOF.

Using:

```bash
-ign_eof
```

tells OpenSSL to keep the encrypted connection alive until the server decides to close it.

This is useful when a service sends additional information after processing user input.

# 7. SSH Public Key Authentication

SSH authentication can occur in two ways.

Password

↓

Shared Secret

SSH Keys

↓

Public Key Cryptography

SSH keys are significantly more secure because authentication is based on mathematical verification rather than knowledge of a secret password.

---

# 8. Public Key vs Private Key

Public Key

- Safe to share
- Stored on the server
- Used only for verification

Private Key

- Must remain secret
- Stored by the user
- Used to prove identity

The private key never leaves the client machine.

---

# 9. SSH Authentication Process

Client

↓

Private Key

↓

Server

↓

Public Key Verification

↓

Authentication Successful

The server verifies ownership without ever receiving the private key itself.

---

# 10. Linux File Permissions

SSH refuses insecure private keys.

Correct permissions:

```bash
chmod 600 private_key
```

Meaning:

Owner

Read

Write

Everyone Else

No Permissions

If permissions are too open, SSH rejects the key.

---

# 11. Why SSH Rejects Weak Permissions

If another user can read the private key:

They can authenticate as the owner.

SSH therefore blocks insecure keys before authentication even begins.

This is an intentional security feature.
