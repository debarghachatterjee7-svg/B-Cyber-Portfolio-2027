# 3. Process Identification

## 3.1 `$?`

Used:

```bash
echo $?
```

This displays the **exit status of the previous command**.

Typical meaning:

```text
0      → success
non-0  → some kind of failure/error
```

This becomes extremely important when writing Bash scripts because scripts can make decisions based on whether a command succeeded.

# 6. `ps -ef`

Used:

```bash
ps -ef
```

This gives another detailed process view.

Important fields:

```text
UID
PID
PPID
C
STIME
TTY
TIME
CMD
```

### PPID

**PPID = Parent Process ID**

A process can be created by another process.

Example:

```text
bash
  └── ps
```

The Bash shell is the parent of the command it launches.

The child's `PPID` points back to its parent.

---

# 7. Understanding PID + PPID

This was one of today's most important concepts.

Think of processes as a family tree:

```text
Parent Process
      |
      +---- Child Process
                 |
                 +---- Another Child
```

For example:

```text
PID 340   bash
PID 684   ps
```

If process 684 was launched from process 340:

```text
PID 684
PPID 340
```

That relationship allows us to understand **how a process was created**.

# 10. Searching Processes with `grep`

Used:

```bash
ps -ef | grep bash
```

and:

```bash
ps -ef | grep cron
```

The pipeline:

```text
ps -ef
   |
   v
grep cron
```

means:

> Take the output of `ps -ef` and search it for lines containing `cron`.

This is an important Linux investigation pattern.

### Real-world example

If a server has many processes and you want to check whether a service is running:

```bash
ps -ef | grep service-name
```

This can quickly narrow down a large amount of output.

Crontab is where scheduled jobs are configured for a user.

### List jobs

```bash
crontab -l
```

Observed:

```text
no crontab for sonu
```

This simply means the current user did not have a personal crontab configured.

### Edit jobs

```bash

```

This opened the editor-selection interface.

The lab interaction confirmed that `crontab -e` is the normal way to create or modify a user's scheduled jobs.

---

# 13. Cron Schedule Structure

A normal crontab entry contains five timing fields:

```text
* * * * * command
│ │ │ │ │
│ │ │ │ └── weekday
│ │ │ └──── month
│ │ └────── day of month
│ └──────── hour
└────────── minute
```

Common symbols:

```text
*       any value
,       multiple values
-       range
/       step
```

Example:

```text
*/10 * * * * command
```

means the command is scheduled every 10 minutes.

---

# 14. Cron vs Crontab

| Term | Meaning |
|---|---|
| Cron | Scheduling service/daemon |
| Crontab | Scheduled-job configuration |
| Cron job | Individual scheduled command/script |
| `crontab -l` | List user's jobs |
| `crontab -e` | Edit user's jobs |
| `crontab -r` | Remove user's entire crontab |

# 15. Lab Questions & Answers

## Q1. What is a PID?

**Answer:**  
PID means Process ID. It is the unique identifier assigned to a running process.

## Q2. What is a PPID?

**Answer:**  
PPID means Parent Process ID. It identifies the process that created/launched the current process.

## Q3. Why are PID and PPID useful?

**Answer:**  
They help us trace processes and understand parent-child relationships.

## Q4. What is the difference between `ps` and `ps -ef`?

**Answer:**  
`ps` gives a limited process view, while `ps -ef` provides a detailed view including UID, PID, PPID, start time and command.

## Q5. What does `ps -aux` help with?

**Answer:**  
It gives a detailed process listing with CPU, memory, process state and command information.

## Q6. Why use `pstree`?

**Answer:**  
It shows processes in a hierarchical tree, making parent-child relationships easier to understand.

## Q7. Why use `grep` with `ps`?

**Answer:**  
It filters the process list so we can quickly find processes containing a specific name.

## Q8. What is Cron?

**Answer:**  
Cron is a Linux scheduling service used to automatically execute commands or scripts at specified times.

## Q9. What does `crontab -l` do?

**Answer:**  
It lists the current user's scheduled Cron jobs.

## Q10. What does `crontab -e` do?

**Answer:**  
It opens the current user's crontab for editing.

## Q11. What does `$?` represent?

**Answer:**  
It contains the exit status of the most recently executed command.

## Q12. Why is `$?` important in Bash?

**Answer:**  
Scripts can use it to determine whether a command succeeded or failed and then choose what to do next.
