# 🔬 Experiment 01 – Exploring Netcat Documentation

## Command

```bash
nc -h
```

### Purpose

To understand the capabilities of Netcat and become familiar with its available command-line options.

### Observation

The help menu displayed numerous options including:

- `-l`
- `-v`
- `-n`
- `-z`
- `-u`

This demonstrated that Netcat supports multiple networking operations beyond simple client connections.

### Conclusion

Netcat is a versatile networking utility capable of operating in several modes depending on the options supplied.

# 🔬 Experiment 02 – Verbose Mode

## Command

```bash
nc -v
```

### Purpose

To observe the behavior of verbose mode without supplying mandatory connection parameters.

### Observation

Netcat displayed its usage instructions because no destination host or port was specified.

### Conclusion

Verbose mode only provides additional connection information when a valid connection command is supplied.

---

# 🔬 Experiment 03 – Listening Mode

## Commands

```bash
nc -l
```

```bash
nc -l 22
```

```bash
nc -l 53
```

```bash
nc -l 80
```

### Purpose

To understand how Netcat behaves when configured as a listening service.

### Observations

- Running `nc -l` alone resulted in an error because no listening port was specified.
- Attempting to listen on ports 22, 53, and 80 produced **Permission denied** errors.

### Explanation

Ports below **1024** are privileged system ports and require administrative privileges.

### Conclusion

A normal user cannot create listening services on privileged ports.

# 🔬 Experiment 04 – Connecting to a TCP Service

## Command

```bash
nc localhost 30000
```

### Purpose

To establish a TCP connection with the service running locally on port 30000.

### Observation

The connection was established successfully.

The terminal waited for user input, confirming that the service expected incoming data.

### Conclusion

Netcat functions as a TCP client and communicates directly with the listening service.

# 🐞 Errors Encountered

## Error 01

Incorrect command:

```bash
cat/etc/bandit_pass/bandit14
```

### Cause

Missing space after `cat`.

### Correction

```bash
cat /etc/bandit_pass/bandit14
```

---

## Error 02

Initially investigated:

```text
~/.ssh/authorized_keys
```

thinking it might contain the account password.

### Investigation

- Entered the directory.
- Identified the file type.
- Read its contents.

### Finding

The file contains SSH public keys rather than passwords.

### Lesson

Always verify assumptions through observation.

---

## Error 03

Attempted to type text after the Netcat session had already terminated.

Linux interpreted the input as Bash commands and returned:

```text
command not found
```

### Lesson

Commands entered after a connection closes are interpreted by the shell rather than by Netcat.
