# 🔍 Practical Activities

## Part 1 — Shell Investigation

Verified the current Linux shell environment by examining:

- Active shell
- Current shell process
- HOME variable
- USER variable
- PATH variable
- Demonstration `.bashrc`

This helped visualize how Linux prepares an interactive shell session.

---

## Part 2 — Understanding the Challenge

Bandit Level 18 presents an intentionally broken login environment.

Instead of attacking the restriction directly, the challenge encourages understanding *why* the restriction occurs.

The modified `.bashrc` immediately logs users out after an interactive SSH login.

---

## Part 3 — Problem Analysis

Instead of asking:

> "How do I bypass the restriction?"

I changed my approach to:

> "Can I avoid opening an interactive shell altogether?"

This reasoning led directly to SSH remote command execution.

---

## Part 4 — Solution

Executed a command directly over SSH:

```bash
ssh bandit18@bandit.labs.overthewire.org -p 2220 "cat readme"
```

Instead of requesting an interactive shell, SSH authenticated first and immediately executed the specified command.

This bypassed the modified `.bashrc` because no interactive shell session was created.

---

# 💡 Key Observation

The restriction was **not** on reading files.

The restriction existed only during shell initialization.

Understanding Linux behaviour made the solution straightforward.

# 🧠 Lessons Learned

- Linux shell initialization directly affects user experience.
- `.bashrc` executes only for interactive Bash sessions.
- SSH is capable of executing commands without opening a normal shell.
- Many CTF challenges test operating system behaviour rather than difficult commands.

---

# ⚠ Common Mistakes

- Attempting repeated interactive logins.
- Ignoring the wording of the challenge.
- Assuming every SSH session requires a shell.
- Focusing on bypassing instead of understanding the restriction.
