# 🎯 Objective

The objective of today's lab was to understand how Linux internally manages running programs and system services.

Instead of memorizing commands, today's focus was on observing how processes are created, organized, and managed by the operating system.

This practical understanding forms the foundation for Linux administration and cybersecurity.

---

# 🧰 Commands Practiced

## 1. Display Current Shell PID

```bash
echo $$
```

### Purpose

Displays the Process ID of the currently running shell.

---

## 2. Display Active Terminal Processes

```bash
ps
```

### Purpose

Shows processes currently running inside the active terminal.

---

## 3. Detailed Process Listing

```bash
ps -aux
```

### Purpose

Displays complete information about every running process.

Information includes

- CPU usage
- Memory usage
- Owner
- PID
- Running command

---

## 4. Full Process Information

```bash
ps -ef
```

### Purpose

Displays

- UID
- PID
- PPID
- Start Time
- Terminal
- Running Command

---

## 5. Process Tree

```bash
pstree
```

### Purpose

Visualizes process hierarchy.

Example

```
systemd
 └── bash
      └── ps
```

---

## 6. Forest View

```bash
ps -ef --forest
```

### Purpose

Displays parent-child relationships using tree formatting.

---

## 7. Find Running Cron Process

```bash
ps -ef | grep cron
```

### Purpose

Filters running processes to locate the Cron daemon.

---

# 📋 Expected Observations

After completing the commands I observed that

- Every terminal has its own Bash process.
- Every command executed becomes a temporary child process.
- Linux assigns every process a unique PID.
- Every process has a parent process.
- Cron continuously runs in the background waiting for scheduled jobs.
- Linux internally maintains a hierarchical process tree.

# 📝 Lab Questions

---

## Q1. Why does Linux assign a PID to every process?

### Answer

Because every running program must be uniquely identified so the operating system can manage, schedule, monitor, and terminate it safely.

---

## Q2. What is the purpose of a PPID?

### Answer

The PPID identifies the parent process that created the current process, allowing Linux to maintain process relationships.

---

## Q3. Why is `pstree` easier to understand than `ps`?

### Answer

`pstree` visually displays how processes are connected, making parent-child relationships much easier to understand than reading raw process tables.

---

## Q4. What is Cron?

### Answer

Cron is a background scheduling service that automatically executes tasks at predefined times or intervals.

---

## Q5. Why do cybersecurity professionals inspect process trees?

### Answer

Because malicious software often creates unusual parent-child relationships. Process trees help detect suspicious behavior, reverse shells, persistence mechanisms, and malware execution.

---

## Q6. What is the difference between `ps -aux` and `ps -ef`?

### Answer

`ps -aux` focuses more on resource usage (CPU and memory), while `ps -ef` emphasizes process hierarchy, ownership, and parent-child relationships.

---

## Q7. Why does every command briefly appear as a process?

### Answer

Every command is executed as its own process. Once the task completes, Linux terminates that process automatically.

---

## Q8. Why is understanding processes important before learning privilege escalation?

### Answer

Privilege escalation often involves manipulating or abusing running services, daemons, or scheduled tasks. Understanding process behavior is essential before attempting advanced Linux security concepts.

---
