# 🧪 Experiment 01
## Identifying the Host System

### Commands Executed

```bash
hostname
hostname -i
```

### Purpose

To identify the current Linux machine and determine its associated IP address.

### Observation

- Successfully retrieved the system hostname.
- Verified the loopback address (`127.0.0.1`) associated with localhost.

### Learning Outcome

Every Linux machine possesses a hostname that uniquely identifies it within a network. The loopback address allows the computer to communicate with itself without sending packets over the physical network.

---

# 🧪 Experiment 02
## Network Connectivity Testing

### Commands Executed

```bash
ping -c 4 google.com
ping -c 2 localhost
```

### Purpose

To compare communication with an external server and the local machine.

### Observation

Google

- Stable packet transmission.
- No packet loss.
- Average latency approximately 60 ms.

Localhost

- No packet loss.
- Extremely low latency.
- Communication completed almost instantly.

### Learning Outcome

External communication depends on Internet routing, resulting in higher latency.

Localhost communication remains entirely inside the operating system and therefore responds significantly faster.

# 🧪 Experiment 03
## Socket Statistics

### Commands Executed

```bash
ss -tuln
ss -tul
ss -tln
```

### Purpose

To inspect TCP and UDP sockets currently active on the system.

### Observation

Observed:

- TCP listening sockets.
- UDP sockets.
- Local addresses.
- Open ports.
- Listening services.

### Learning Outcome

The `ss` utility displays socket information, allowing administrators and cybersecurity professionals to inspect active network services and open ports.
