# 📖 Background

Traditional TCP communication sends information without encryption unless an additional security layer is introduced.

Modern internet services rely on **TLS (Transport Layer Security)** to:

- Encrypt transmitted information.
- Verify server identity.
- Protect user credentials.
- Prevent data interception during transmission.

OpenSSL provides the client-side implementation required to communicate with SSL/TLS-enabled services directly from the Linux terminal.

## Activity 01 — Verifying OpenSSL Installation

Command:

```bash
openssl version
```

---

## Activity 02 — Establishing a Secure TLS Connection

Connected securely to the Bandit challenge service using OpenSSL.

Command:

```bash
openssl s_client -connect localhost:30001
```

During the connection I observed:

- TCP connection establishment
- Certificate exchange
- Certificate verification status
- TLS handshake completion
- Negotiated encryption cipher
- Secure session creation

---

## Activity 03 — Certificate Analysis

Observed the server certificate and examined:

- Certificate chain
- Subject
- Issuer
- Public key information
- Verification results

A self-signed certificate warning appeared, demonstrating that encrypted communication can still be established even when the certificate is not issued by a trusted Certificate Authority.

---

## Activity 04 — Secure Authentication

Submitted the password obtained from Bandit Level 14 through the encrypted TLS session.

The server successfully verified the password and returned the credentials for the next level.

---

## Activity 05 — Local Environment Experiment

Repeated the same OpenSSL command inside the local Linux environment (WSL).

Result:

```
Connection Refused
```

This experiment demonstrated that:

- `localhost` always refers to the current machine.
- My local Linux system did not have any service listening on port **30001**.
- The successful connection on Bandit occurred because the Bandit server hosted the required TLS service.

This comparison significantly improved my understanding of networking fundamentals.

# 🔍 Key Observations

- SSL/TLS communication requires a handshake before any application data is exchanged.
- OpenSSL performs both TCP communication and TLS negotiation.
- Self-signed certificate warnings are informational and do not necessarily indicate a failed connection.
- Encrypted communication protects credentials during transmission.
- Localhost represents different systems depending on the environment in which commands are executed.

# 🚧 Challenges Faced

- The warning was generated because the certificate was self-signed.
- The secure TLS session was still established successfully.
