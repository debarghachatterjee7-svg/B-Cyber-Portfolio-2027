# 📋 Practical Tasks Performed

## Task 1 — Explore Cron Configuration

Listed cron configuration files.

```bash
ls /etc/cron.d/
```

### Observation

Multiple scheduled jobs exist.

Each file represents an automated task executed by Linux.

---

## Task 2 — Inspect Scheduled Job

Opened the Bandit22 cron configuration.

```bash
cat /etc/cron.d/cronjob_bandit22
```

### Observation

Discovered the system automatically executes

```
/usr/bin/cronjob_bandit22.sh
```

every minute.

---

## Task 3 — Analyze the Script

Opened the shell script.

```bash
cat /usr/bin/cronjob_bandit22.sh
```

Observed:

- Creates a predictable filename
- Reads Bandit22 password
- Writes password into a temporary file

---

## Task 4 — Retrieve Output

Opened the generated temporary file.

```bash
cat /tmp/<generated_filename>
```

Successfully recovered the password for Bandit22.

# 👨‍🏫 Professor Questions (Answered)

### Q1. Why did reading the cron configuration solve the challenge faster?

Because configuration files tell us exactly **what the system is doing**, eliminating guesswork.

---

### Q2. Why are cron jobs important in Linux?

They automate repetitive administrative tasks without human intervention.

---

### Q3. Why inspect the shell script instead of searching the filesystem?

The script explains the program's logic directly. Understanding the logic is more reliable than searching blindly.

---

### Q4. Why was the password stored in `/tmp`?

The script temporarily stores generated output there so another process or user can read it.

---

### Q5. What investigation skill was improved today?

Tracing **program execution** instead of searching randomly.

---

### Q6. What mistake was avoided after the initial attempt?

Continuing random exploration.

Instead, I followed the official execution path.

---

### Q7. If this were malware, what would the investigation look like?

Exactly the same.

Security analysts often begin by checking:

- Scheduled tasks
- Startup scripts
- Cron jobs
- Shell scripts

to understand malicious persistence.

---

### Q8. Why is execution flow more important than memorizing commands?

Commands only provide tools.

Understanding execution flow tells you **where to use them**.

---

### Q9. Which mindset improved the most today?

Investigator mindset.

Instead of asking:

> "Where is the password?"

I asked:

> "How does this system create the password?"

---

### Q10. What should improve next?

Become faster at reading shell scripts and predicting program behavior before executing commands.

# 🎓 Mentor Guidance

Today's work marks an important shift.

Earlier Bandit levels focused on files and commands.

Today introduced **system investigation**.

Going forward, whenever you encounter a problem:

1. Read the configuration.
2. Identify what executes.
3. Read the script.
4. Understand the logic.
5. Only then execute commands.

This five-step process is exactly how professional Linux administrators and cybersecurity analysts troubleshoot systems.
