# 🔍 Observations

One of the most valuable observations today was understanding the meaning of **localhost**.

Initially, I expected:

```
localhost:30001
```

to behave the same on both Bandit and my own Linux environment.

Instead, I observed that:

- On the Bandit server, the required TLS service was running.
- On my local WSL environment, the same command returned **Connection Refused** because no service was listening on that port.

This reinforced the idea that `localhost` always refers to the current machine, not a universal server.

---

# ⚠️ Initial Confusion

At first, I believed the certificate verification warning meant something had gone wrong.

After analysing the output, I understood that:

- The connection was still encrypted.
- The warning appeared because Bandit uses a self-signed certificate.
- A self-signed certificate is acceptable in this controlled learning environment even though browsers would normally warn users.

Understanding this distinction removed an important misconception.

---

# 💡 Biggest Learning

Today changed how I think about secure communication.

Previously, I saw HTTPS as simply "the secure version of HTTP."

Now I understand that a secure connection must first establish trust, negotiate encryption, and create a protected communication channel before any sensitive information is exchanged.

The password itself is not what provides security—the encrypted session does.
