# 🧠 Concepts Learned

## What is Netcat?

Netcat is a command-line networking utility used to establish TCP or UDP connections and exchange raw data between a client and a server.

Unlike SSH, Netcat does not provide a Linux shell. It simply creates a communication channel between two endpoints.

---

## Client–Server Communication

I learned that almost every network application follows the client–server model.

- A **client** initiates a connection.
- A **server** waits for incoming connections on a specific port.
- Once connected, both sides exchange data.

Understanding this concept helped me understand why Bandit Level 14 required Netcat instead of SSH.

---

## Network Services

A network service is simply a program waiting for incoming connections.

Examples include:

- SSH
- HTTP
- HTTPS
- DNS

Bandit Level 14 runs its own service on **localhost:30000**, which waits for the current level password before returning the password for the next level.

---

## SSH vs Netcat

Today I clearly understood the difference:

| SSH | Netcat |
|------|---------|
| Opens a remote shell | Communicates with a service |
| Executes Linux commands | Sends and receives data |
| Used for remote administration | Used for general network communication |

# 🐞 Mistakes & Debugging

## Mistake 1

Initially I typed:

```bash
cat/etc/bandit_pass/bandit14
```

instead of:

```bash
cat /etc/bandit_pass/bandit14
```

The missing space caused Bash to interpret it as a command name.

I immediately identified the mistake and corrected it.

---

## Mistake 2

I initially became confused after discovering:

```text
~/.ssh/authorized_keys
```

I thought the password might be stored there.

To verify my assumption, I:

- Entered the directory
- Used `file`
- Opened the file

I discovered that **authorized_keys contains SSH public keys**, not account passwords.

This taught me an important cybersecurity lesson:

> Never assume. Verify.

---

## Mistake 3

While experimenting with Netcat, I typed text after the connection had already ended.

Linux responded with:

```text
command not found
```

Initially this confused me, but I later understood that I was already back in the Bash shell instead of inside the Netcat session.
