# 🧠 Theory Learned

Unlike previous Bandit levels, today's challenge focused on understanding **Linux execution context**.

I learned that Linux differentiates users internally using numerical identifiers (UIDs), while groups define shared permissions. I also explored environment variables that configure shell behaviour and executable search paths.

The introduction to **SUID (Set User ID)** demonstrated how a program can temporarily execute with the permissions of its owner instead of the user launching it.

## OverTheWire Bandit Level 19

Inside the Bandit server, I first inspected the available files and discovered a binary named `bandit20-do`.

Rather than executing random commands, I verified:

- My current identity using `id`
- The executable type using `file`
- The effective execution context using:

```bash
./bandit20-do whoami
```

The result confirmed that the binary executed with **bandit20** privileges.

Using this understanding, I successfully executed:

```bash
./bandit20-do cat /etc/bandit_pass/bandit20
```

which securely retrieved the password for the next level.
