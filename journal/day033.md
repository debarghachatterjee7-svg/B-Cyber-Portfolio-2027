# 🧠 Theory Learned

Today's level introduced one of the most important Linux administration concepts:

## Cron (Job Scheduler)

Cron is a Linux service that executes commands automatically based on time schedules.

Examples:

- Every minute
- Every hour
- Every day
- Every week
- At system startup

Large servers depend heavily on cron for automation.

---

## Execution Flow

Instead of looking directly for the password, today's task required tracing the execution path.

```
Cron Configuration
        ↓
Scheduled Job
        ↓
Shell Script
        ↓
Temporary File
        ↓
Password
```

This teaches how to investigate systems rather than randomly searching them.

---

# 🧪 Practical Work

## Step 1

Listed cron configuration directory.

```bash
ls /etc/cron.d/
```

Observed multiple cron jobs.

---

## Step 2

Opened Bandit22 cron configuration.

```bash
cat /etc/cron.d/cronjob_bandit22
```

Found:

```
/usr/bin/cronjob_bandit22.sh
```

---

## Step 3

Opened the shell script.

```bash
cat /usr/bin/cronjob_bandit22.sh
```

Observed that it:

- generates a filename
- writes Bandit22 password into /tmp

---

## Step 4

Opened the generated file.

```bash
cat /tmp/<generated_filename>
```

Successfully retrieved Bandit22 password.

# 🧠 Professor Questions

## Why didn't we search the filesystem?

Because the system already told us where to look.

Reading configuration is faster and more reliable.

---

## Why was the password stored in /tmp?

The script temporarily writes data there so another process or user can access it.

---

## What is the biggest lesson from today's level?

Always understand how a system works before trying random commands.
