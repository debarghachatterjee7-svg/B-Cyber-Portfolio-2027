# 3. Exit Status — `$?`

I practiced:

```bash
echo $?
```

This shows the exit status of the previous command.

Generally:

```text
0      → success
non-0  → some form of failure/error
```

### Why it matters

This becomes very important in Bash scripts.

A script can perform an action and then check:

```bash
echo $?
```

or use the status directly in conditional logic.

### Real-world use

For example, an automation script might:

```text
run backup
 ↓
check result
 ↓
if successful → continue
if failed     → report/retry
```

This is one of the foundations of reliable automation.

# 4. Processes

A command that is running is associated with a process.

Each process has an identity called a:

## PID — Process ID

Example:

```text
PID = 594
```

The PID identifies that particular running process.

## PPID — Parent Process ID

PPID identifies the process that launched the current process.

For example:

```text
bash
 └── command
      └── child process
```

The child process has its own PID and the PID of its parent appears as its PPID.

### Why this matters

PID answers:

> "Which process is this?"

PPID helps answer:

> "Where did this process come from?"

That second question is extremely useful in system investigation.

# 5. Process Inspection

I practiced commands including:

```bash
ps
ps -aux
ps -ef
pstree
pstree -p
```

## `ps`

Provides a basic process snapshot.

## `ps -aux`

Provides a more detailed process view including information about users and resource usage.

## `ps -ef`

Provides a detailed process listing where PID and PPID relationships can be inspected.

## `pstree`

Displays processes as a hierarchy.

```bash
pstree
```

With PIDs:

```bash
pstree -p
```

### Why use both?

`ps` is useful when I need detailed information.

`pstree` is useful when I need to understand relationships.

A good investigator may use both instead of depending on only one command.

# 6. Filtering Process Information

I also practiced the idea of combining process commands with `grep`.

Example:

```bash
ps -ef | grep cron
```

or:

```bash
ps -ef | grep bash
```

The logic is:

```text
ps -ef
   ↓
all relevant processes
   ↓
grep
   ↓
only lines matching my search
```

### Important thinking pattern

When the output is huge, do not immediately try to memorize or manually inspect everything.

Instead:

```text
Generate information
      ↓
Filter
      ↓
Inspect relevant result
      ↓
Investigate further
```

This is a much better cybersecurity workflow.

# 7. Cron

Cron is a Linux scheduling mechanism used to execute commands or scripts automatically.

Examples of legitimate real-world tasks:

- backups
- log cleanup
- report generation
- monitoring
- maintenance
- temporary-file cleanup
- scheduled synchronization

A Cron process can be visible through process inspection.

For example:

```bash
ps -ef | grep cron
```

# 8. Crontab

I learned the basic user-level Crontab workflow.

```bash
crontab -l
```

Lists the current user's scheduled jobs.

```bash
crontab -e
```

Opens the current user's Crontab for editing.

A Cron entry follows the basic structure:

```text
* * * * * command
│ │ │ │ │
│ │ │ │ └── weekday
│ │ │ └──── month
│ │ └────── day of month
│ └──────── hour
└────────── minute
```

Common scheduling symbols:

```text
*  → any value
,  → multiple values
-  → range
/  → step
```

### Important practical lesson

I should understand the schedule before putting a command into Crontab.

A mistake in scheduling can make a command run far more often than intended.

For future labs, use harmless test commands and temporary files rather than risky system modifications.

# 9. Today's Process Investigation Method

A useful general workflow I learned today is:

### Step 1 — Identify the situation

Ask:

```text
What am I trying to find?
```

### Step 2 — Get broad information

For processes:

```bash
ps -ef
```

### Step 3 — Filter

```bash
ps -ef | grep <keyword>
```

### Step 4 — Understand relationships

```bash
pstree -p
```

### Step 5 — Inspect the relevant process

Look at:

```text
PID
PPID
USER
CMD
```

### Step 6 — Ask whether it is expected

This is where cybersecurity thinking begins.

Do not assume:

> "I found a strange process, therefore it is malicious."

Instead ask:

```text
Who owns it?
What launched it?
What is its parent?
What command is running?
Is it a known service?
Is it scheduled?
Does its behavior make sense?
```

# 14. Questions I Should Be Able to Answer

### What is PID?

The unique identifier of a running process.

### What is PPID?

The PID of the process that launched the current process.

### Why is PPID useful?

It helps trace process origin and relationships.

### Why is `pstree` useful?

It presents process relationships as a hierarchy.

### Why use `grep` after `ps`?

To filter a large process listing to relevant entries.

### What is Cron?

A Linux scheduling mechanism for automatically running commands/scripts.

### What is Crontab?

The interface/configuration used to define scheduled jobs for a user.

### Why is `$?` important?

It lets scripts determine whether a previous command succeeded or failed.

### Why is `env | sort` useful?

It displays environment variables in an easier-to-search sorted order.
