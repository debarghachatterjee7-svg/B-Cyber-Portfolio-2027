# 🧠 Theory Learned

## Linux Process Architecture

A process is a running instance of a program.

Unlike files stored on disk, processes actively consume CPU time, memory and other operating system resources.

Every running application is represented internally as a process.

---

## Parent–Child Relationships

One of today's most important concepts was understanding that Linux processes form a hierarchy.

Every process is created by another process.

Understanding these relationships makes debugging and security analysis significantly easier.

---

## Process Monitoring

Using tools like:

- `ps`
- `ps -ef`
- `ps aux`
- `top`

I learned that Linux provides multiple ways to inspect running processes depending on whether I need a quick snapshot or live monitoring.

---

## Process Management

Linux provides complete control over process execution.

Processes can be:

- Started
- Suspended
- Resumed
- Sent to the background
- Returned to the foreground
- Terminated

This is essential knowledge for both administrators and security professionals.

---

## `/proc` Filesystem

Today's most interesting concept was the virtual `/proc` filesystem.

Rather than storing ordinary files, it exposes real-time kernel and process information.

This provides detailed insight into running processes without requiring additional software.

---

## Shell Operators

Today's shell operators significantly improved my understanding of command execution.

I learned how Linux handles:

- Error output
- Conditional execution
- Background execution

These operators make automation scripts significantly more reliable.

# 🔍 Important Observations

Several observations stood out today.

- Linux assigns every running process a unique PID.
- Every process has a parent process.
- `top` continuously updates information whereas `ps` provides a static snapshot.
- `/proc` changes dynamically as processes start and stop.
- Error redirection dramatically improves command readability.
- Background execution allows multitasking without blocking the terminal.

# 👨‍🏫 Professor Reflection Questions

### Why does Linux assign every process a PID?

To uniquely identify every running program and allow the operating system to manage it individually.

---

### Why is `/proc` important?

It provides real-time information about processes and the operating system without requiring additional monitoring tools.

---

### Why should administrators monitor running processes?

To identify abnormal behaviour, resource consumption and potential security threats.

---

### What was today's most useful command?

`top`

It demonstrated Linux behaviour dynamically rather than statically.

---

### Why is understanding parent-child relationships useful?

It allows analysts to trace how processes were created, helping identify suspicious execution chains.

---

### How do today's concepts relate to cybersecurity?

Nearly every Linux attack, malware sample or privilege escalation technique eventually interacts with running processes.

Understanding process behaviour is therefore essential for both attackers and defenders.
